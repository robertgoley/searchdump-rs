# L-804a: exit-code review of the L-804 fault-injection runs

Owner decision 2026-11-14 (t83u): "I think exit codes should be reviewed as they could have different error points."
Source data: `results/local/L-804.json` / `L-804.md` (L-804, `scripts/load/faults.py L1L`, es717-plain 7.17.29,
1M `load-logs` docs, limit 1000, concurrency 8, default retries). Code read at `main` after L-645b.

## Exit codes the binary can return (src/lib.rs `exit_code`, src/main.rs)

| Code | Meaning | Where it is decided |
|---|---|---|
| 0 | success | `run` returned Ok |
| 1 | any other error (network, cluster, I/O, refused data) | `exit_code` fallback |
| 2 | usage error (`UsageError`) | `exit_code` |
| 3 | finished, but documents were not written (`WriteFailures`) | `exit_code`; built at the end of a run from the failed-item counter |
| 128+sig (130, 143) | stopped by SIGINT / SIGTERM (`signals::Interrupted` / `Stopped`) | `exit_code` |
| 101 | panic in the main thread (runtime thread join failed) | src/main.rs |

## Summary

- All 11 exit codes are **correct** for what happened (no exit 0 with loss; 3 only for "finished with failed writes";
  1 for runs that could not finish).
- **Distinctness**: exit 1 mixes two classes a wrapper would treat differently:
  - transient / rerun-safe failures where nothing was committed (E1-E4: cut or restarted connections, lost
    scroll/PIT context, overload after all retries), and
  - permanent failures that need a change first (401/403, refused mappings or policies, bad input data, a target
    index deleted mid-restore, ...).
- **Messages**: E1, E2 and E5 are clear and say what to do. E3/E4 were the raw ES rejection only; fixed (message
  only, no behaviour change). E4 reads differently from E3 because of the flattened output-task prefixes.

## Fix made in L-804a (message only)

- `http/retry.rs` `EsHttpError` Display: a final HTTP 429 names `--retryAttempts`, `--retryDelay`, `--concurrency`,
  `--limit`, `--maxSockets`. Unit test `final_429_suggests_retry_and_load_knobs`. Exit codes unchanged.
