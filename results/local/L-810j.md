# L-810j: no user-admin or init-script tools in the Debian images

Owner decision 2026-11-14 (answer to the CI review): "Remove the extra user-admin tools in the image
build and keep the check strict".

## Problem

Since L-810i the `security` workflow's `image` job (default `base=dhi-debian`) failed in
`make test-image`: "undocumented executables". `openssh-client`'s dependencies on the dhi.io Debian base
install `passwd`, `login.defs`, `init-system-helpers` and an `adduser` example hook. The dhi-debian
baseline in L-810i was edited by hand (no dhi.io login on the box), so it did not list them. The
31 extra files from main 20e3832 (security run 43654372242):

- passwd: chage, expiry, chgpasswd, chpasswd, groupadd, groupdel, groupmod, grpck, grpconv, grpunconv,
  newusers, pwck, pwconv, pwunconv, shadowconfig, useradd, userdel, usermod, vipw;
- init-system-helpers: deb-systemd-helper, deb-systemd-invoke, service, update-rc.d, invoke-rc.d;
- adduser: /usr/share/doc/adduser/examples/adduser.local;
- dpkg maintainer scripts: init-system-helpers.postinst, login.defs.postinst, passwd.{preinst,postinst,prerm,postrm}.

## Change

- `Dockerfile` `runtime-shell`, apt branch only: after the `openssh-client` install, `rm -f` of exactly
  those files (plus the `vigr` symlink to `vipw`). Alpine (`openssh-client-default`) pulls none of
  them and is unchanged. dhi-static (no package manager) is unchanged.
- `docker/image-binaries.*.txt`, `scripts/test-image.sh` and the grype/trivy ignore files: **unchanged**,
  so the check stays strict and has no new allowlist entries.
- The packages stay in the dpkg database (only files are removed), so SBOM and CVE scan results do not change.
