## 1. Safe-simple live (256m heap, bash examples, `scripts` harness `safe_simple.py`)

The chain-1g run (14:09-14:10 EST, binaries without the fix) reported `SAFE-DONE es710/es819/os2 256m FAIL`. Cause (real failure,
not harness): the example preflight runs `searchdump --input=URL/INDEX --output=/dev/null --type=data --serverLimits=check`,
and `validate()` refused `/dev/null` as "a character device" with the usage exit 2 before the probe ran; the preflight maps
every exit 2 to "explicit flags exceed what the cluster can take". Fix (from wip b40d7b9): `--serverLimits=check` never validates
the output path; `_preflight.sh` and the README say exit 2 can also be a usage error; tests `l2_009_*` fail without the fix.

Rerunning exposed a **second real bug**: `safe-simple-dump.sh` (bash, docker-podman, kubernetes) wrote `INDEX.data.json.gz`
without `--fsCompress`, so the file was plain JSON under a `.gz` name (restore auto-detects, so the restore passed; the harness
digest reader refused it). Fix: the data step passes `--fsCompress`; the l2_009 example test now asserts the gzip magic bytes.

Result after both fixes (release bins built from this tree, ports 19258, isolated podman store): every step exit 0, node alive,
`server limits` line present on every step (probed), restored digests equal to the source:

| engine | version | heap | dump/restore single (pmc, fat) | multi dump/restore | result |
|---|---|---|---|---|---|
| es710 | 7.10.2 | 256m | 4 steps exit 0, digests equal | 2 steps exit 0, digests equal | **PASS** |
| es819 | 8.19.23 | 256m | same | same | **PASS** |
| os2 | 2.19.7 | 256m | same | same | **PASS** |

Raw: `/workspace/perf-1.2/live/safe-{es710,es819,os2}-256m.json` (14 steps each, 6 exit codes, all 0).
