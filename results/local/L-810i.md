# L-810i: OpenSSH client in the container images (sftp://)

Owner decision 2026-11-14 (t83u): "Add openssh-client to the image for now to address SFTP."

## Change

- `Dockerfile` `runtime-shell` stage (dhi-debian default, dhi-alpine, public, alpine):
  - apk bases: `apk add --no-cache openssh-client-default` (the `ssh` binary only, no keysign);
  - apt bases: `apt-get install -y --no-install-recommends openssh-client`, apt lists/caches/logs
    removed, `chmod u-s /usr/lib/openssh/ssh-keysign`; the stage then runs `ssh -V`.
- `runtime` (dhi-static, COPY-only, no package manager): unchanged, still no SFTP.
- `scripts/test-image.sh`: new checks "OpenSSH client /usr/bin/ssh present" (not for dhi-static) and
  "ssh-keysign not setuid".
- `docker/image-binaries.*.txt`: public and alpine regenerated from the builds (union with the old
  lists, since podman's export lists setuid files and hard links differently from the docker export
  that made the old lists); dhi-debian and dhi-alpine got the same package deltas **without a build**
  (no dhi.io login on this box) and must be confirmed with `scripts/test-image.sh <img> <type> --update`
  when the dhi.io token is available (CI's image job does that build).

## Options for the owner

1. Accept the Debian openssh-client/krb5 findings (add fix-state-scoped ignore rules as in L-808d) and

2. SFTP only in the Alpine images (no High findings): keep the Debian images without `ssh` and

trivy rules added; with them grype and trivy report none of these ids on the local Debian build. Merged to `main`
as one squashed L-810i commit; the branch `wip/L-810i` was deleted on 2026-11-14 with owner approval (t86u).
