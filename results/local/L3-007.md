# L3-007: 1.3-G same-host ratio: os3-plain Suite A, 1.1.0 vs 1.2.0 on grokbox

Two fresh-engine passes on grokbox (OpenSearch 3.9.0 plain, 4096m, `--reps 3 --skip-node`, release assets):
1.2.0 16:22-16:29 ET (`L3-002/os3-plain-12/`), 1.1.0 16:33-16:41 ET (`L3-007/os3-plain-11/`; this pass already
had the L3-002 DELETE wait; a `cargo test` build ran at nice 19 for ~1 min during it). 37 cases, median
1.2/1.1 = **1.00**.

**1.3-G conclusion:** the kvmsvr1 os3-plain regression does not reproduce on another host, in the same case
order, with fresh engines, nor interleaved on one engine (L3-001), and 1.2.0 sends exactly the 1.1.0
requests with `--noDefaultDataFlags` (L3-001 traces). It is an engine/host-state effect of that one pass, not
a 1.2.0 code regression. Proposed: close 1.3-G as "not a product regression"; keep the L3-002 harness
changes; ask kvmsvr1 to rerun os3-plain 11 and 12 (ABA order) if Robert wants it confirmed there.

**Side finding (small, single-index sliced dumps):** `dump-scroll-s1` 1.34, `dump-pit-s1` 1.52,
`dump-scroll-s2` 1.41 (+0.2-0.4 s) on grokbox; kvmsvr1 os2-plain also showed dump-pit-s1 1.32 / dump-pit-s8
1.29. Plain `searchdump` data runs in Suite A do NOT pass `--serverLimits=off`, so 1.2 runs its `auto`
probe (`_nodes/stats`, settings, `_stats` for the average doc size) there: that is a flag difference, not
equal-flag code speed. Characterised in L3-009.
