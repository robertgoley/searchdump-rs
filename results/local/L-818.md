# L-818: standard low-memory engine test set (LOAD-LM, `scripts/load/lowheap.py`)

Owner request 2026-11-14 (t100u/t101u): the 256 MB / 384 MB heap runs behind 1.1-10 were one-off
scripts, and no standard suite runs below 768 MB (perf) or 512 MB (CI integration tests), so nothing
would catch 1.1-10 coming back. "Add a set of tests for that use case."

## What was added

- `scripts/load/lowheap.py`: 4 engines x 2 heaps (256m, 384m) x 2 datasets; `searchdump-multi` dump
  and load with **no extra flags**; pass = exit 0 (no 429 retries exhausted), count and digest equal to
  the source, node alive after every step, no open search context. `--regression` (optional) repeats
  dump and load with the pre-1.1-10 flags and records whether they fail; not asserted.
- Datasets (generated, seeded, cached under `$LOAD_WORK/lowheap-data`): `pmc` 20,000 documents,
  21.6 KB average (word text); `fat` 3,000 documents, 78.0 KB average (base64 noise). `--pmc FILE`
  takes the real Rally pmc file instead.
- Documented in `scripts/load/README.md` ("Low-memory engines") with a pointer from
  `scripts/perf/README.md`.

### main (old searchdump-multi defaults), default mode

`lowheap.py --engines es710,es819 --heaps 256m` with main's binaries (e3bb8ca code; searchdump-multi
unchanged since): **FAIL as expected**: every default-flag dump failed (ES 7.10.2: node OOM, exit 1;

gap; it passes there once 1.1-10 is ported (the owner's call).

### Script fixes after the full run

- The OOM counter now counts only `java.lang.OutOfMemoryError` lines. Before, it also counted the JVM's
  own `-XX:+HeapDumpOnOutOfMemoryError` option line, so `oom_log_lines` in L-818.json reads 1 on
  nodes that never ran out of memory. Rechecked: ES 7.10.2 256m fat with `--regression` PASS, 3 real
  OutOfMemoryError lines after the old-flag dump.
- Summary table only: "-" instead of 1000 when no page note was printed, and "node" reads DOWN only
  when a step that ran left the node down.
