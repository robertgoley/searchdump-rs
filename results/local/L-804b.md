## Exit-code classification (P1)

| Source | Exit |
|---|---|
| Connect refused / reset / timeout / body cut off mid-transfer (after the retries) | 4 |
| Response body that does not decode (broken gzip header, unrequested compression) | 1 |
| DNS failure that is not a permanent NXDOMAIN-style error | 4 |
| HTTP 429 or 5xx (after the retries) | 4 |
| Scroll context lost (initial search continuation, 404 `search_context_missing`) | 4 |
| Plain-HTTP request to a port whose connection closes (`if this port serves HTTPS` hint) | 4 (retried; indistinguishable from a half-closed socket) |
| TLS certificate / protocol errors, `invalid HTTP version` on http:// | 1 |
| EMFILE (`Too many open files`) | 1 |
| Restore that already sent documents without `_id`, then fails transiently (`NotRerunSafe`) | 1 |
| Other 4xx, mapping, auth, file I/O, panics, everything else | 1 |
| Usage 2, failed writes 3, signals 130/143 take precedence as before | unchanged |

Precedence in `exit_code`: usage (2) → write failures (3) → signal (130/143) → transient (4) → 1.
`searchdump-multi` keeps its own codes.
