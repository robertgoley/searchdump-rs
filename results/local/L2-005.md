## What changed (section 6 table, piece by piece)

| 1.1-10 piece | 1.2 |
|---|---|
| `DATA_FLAGS` `--limit=1000`, `--maxBulkBytes=16mb` | **Rewritten**: `DATA_FLAGS` keeps only run-control flags (`--scrollTime=10m --retryAttempts=5 --retryDelay=2000 --timeout=300000`); page and bulk come from `sizing::Plan`. |
| `DEFAULT_DATA_LIMIT`, `PAGE_STORE_BUDGET` | **Moved** into `mod sizing` as the `off` profile (`OFF_LIMIT` 1000, `OFF_BULK` 16 MiB, `PAGE_STORE_BUDGET` 16 MiB). |
| `fn page_limit_for` | **Kept** as the `off`-profile wrapper (identical results); `auto`/`min` use `limits::page_docs` on the byte budget. |
| `Cluster::avg_doc_bytes` (per-index `GET {index}/_stats/docs,store`) | **Deleted**. One `GET _stats/docs,store?level=indices&expand_wildcards=open,hidden&filter_path=...` in the parent for every index (a per-target call only for a target that answer did not name, e.g. a data stream). |
| Per-index block in `dump_one` rewriting `--limit` | **Deleted**. The parent passes each child `--limit=N --maxBulkBytes=M --serverLimits=off` (children never probe); a `note:` line only for an index whose page is below the default. |
| `merge_data_flags` | **Kept** (user flags after `--` still win); `merge_data_flags_owned` for computed defaults. |
| `--noDefaultDataFlags` | **Kept**; implies `--serverLimits=off` and no sizing flags at all (the perf suite's mode). |
| Test `default_data_flags_are_small_heap_safe` | **Replaced** by `server_limits_off_reproduces_1_1_0_flags` and `run_control_flags_unchanged`; plus `auto_plan_sizes_from_fixture_limits` (worker-first, 256m fixture, parallel 1 stays 1). |
| Test `page_limit_shrinks_for_large_documents` | **Kept** as the `off`-profile table. |

New:

- **Worker-first policy (4.1):** if `--parallel` pages of the largest index (at `MULTI_MAX_PAGE` = 5000,
  the 1.0 page) exceed the in-flight budget, fewer workers are assumed first (down to 2, or 1 when 1
  was asked), and only then the page shrinks (`reason` `budget`); an index whose documents are too large
  for one page gets a smaller page (`large-docs`).
- **Byte-budget scheduler (4.1):** next to the `--parallel` semaphore, a weighted semaphore of
  in-flight KiB: each running dump holds its index's estimated page bytes, so large-document indices run
  fewer at once while small ones still run `--parallel` at once.
- **Load side (4.4):** bulk bytes per worker = bulk budget / `--parallel`, never above
  `http.max_content_length` - 1 MB (10 MiB on AWS); `--limit` 5000 when bulks may be >= 64 MB, else 1000.
- **Manifest (7):** `server_limits` object (mode, source, per-node limits, budget, `parallel`,
  `fit_parallel`, `bulk_bytes_per_worker`) and per-index `sizing` (`limit`, `max_bulk_bytes`, `reason`).
- `--serverLimits=check` on the parent: prints the line and each index's page, exits 0, or 2 when a flag
  after `--` is above an index's computed page; nothing is written.
- An older child binary without `--serverLimits` is detected (`accepts_server_limits`) and gets only
  `--limit`/`--maxBulkBytes`.
