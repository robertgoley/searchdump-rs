## Findings

1. **Constant docs in flight is not enough on 256m.** 2x5000, 4x2500 and 8x1000 keep P x L at
   8,000-10,000 docs, yet on es710 256m pmc (~22 KB docs, ~110 MB per 5000-doc page) every config
   killed the node (`DOWN`, connection refused afterwards), and on fat only 2x5000 survived. ES 7.10's
   parent breaker did not stop it in time: the node went out of memory instead of answering 429.
2. **ES 8.19 answers 429 instead of dying**: 2x5000 and 4x2500 pmc on 256m fail after all retries with
   `circuit_breaking_exception`, the node survives.
3. **Fewer workers with full pages beat more workers with smaller pages** where both fit (es819 384m
   pmc: 2x5000 passes, 4x2500 fails with 296 breaker 429s; es710 384m pmc: 2x5000 passes, 4x2500 kills
   the node). It is not monotonic: es819 384m pmc 8x1000 passed again, so smaller pages do help once
   each response is small (~22 MB). Single runs per cell, so expect noise at the edges. Taken together,
   2 workers with a page that fits is the most reliable choice, which backs the worker-first rule:
   reduce parallelism to min(2, P) before shrinking pages (L2-005).
4. **Load 429s are indexing-pressure rejections that mostly retry and succeed** (fat 4x2500 / 8x1000),
   except es819 256m 8x1000 (pmc and fat) where they exhausted the retries (exit 1). The 1.2-1c bulk
   split on a size 429 (L2-003) targets exactly this.
5. Wall time when everything fits differs little across configs (fat 384m dump 1.4-3.7 s), so a
   conservative auto plan costs little where it matters.

**Consequence for the policy (section 4.1):** page bytes per worker = 25 % of the free parent breaker
(auto) / 12.5 % (min), bytes in flight capped at 50 % / 25 %, and the worker count is cut first. On the
same es819 256m node the 1.2 `--serverLimits=auto` build chose ~330 docs per page and parallel 2 for
the largest index and passed dump and load of all 20,000 pmc docs (live check, box file
`/workspace/perf-1.2/live/multi-es819-256m.json`); the full auto / off lowheap counts are in L2-006.

Not run here: OpenSearch engines, and `auto`/`off` configs in this matrix (the 1.1.0 build has no
`--serverLimits`; 1.2 auto vs off on all engines is the L2-006 lowheap run).
